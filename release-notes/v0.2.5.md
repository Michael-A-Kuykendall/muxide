# Muxide v0.2.5 — MP4 Spec Compliance, Codec Box Correctness, Audio/Video Interop

Released: May 20, 2026

## Summary

This release resolves a sweep of MP4 spec-compliance issues found during a structured audit,
adds a functional H.264+AAC audio/video interop test verified by ffprobe and ffmpeg decode,
and corrects a panic introduced in v0.2.4 when the codec boxes for HEVC, AV1, and VP9 were
built with all-zero config fields.

All 236 tests pass. All supported codec paths (H.264, H.265, AV1, VP9 + AAC, Opus) have been
verified end-to-end against real ffmpeg-generated bitstreams.

---

## Critical Bug Fixes

**Tracks disabled in all players (`build_tkhd_box`, `muxer/mp4.rs`)**
`tkhd` flags were 0, meaning `track_enabled` and `track_in_movie` bits were clear.
ISO 14496-12 §8.3.2 requires both bits set. Fixed to `0x0000_0003`.
*Symptom before fix*: video and audio tracks reported as disabled by ffprobe
(`disposition:default=0`); some players silently skipped them.

**VP9 vpcC box was malformed (`build_vpcc_box` / `build_vpcc_fmp4`, `muxer/mp4.rs`, `fragmented.rs`)**
Missing FullBox header (version + flags), wrong bit-packing of the
`bit_depth/chroma_subsampling/full_range_flag` byte, and missing
`codecInitializationDataSize` field. All three issues fixed.

**HEVC/AV1 fragmented codec boxes were all-zero (`fragmented.rs`)**
`build_hvcc_fmp4` and `build_av1c_fmp4` emitted placeholder/default config fields
instead of extracting real values from the SPS/sequence-header OBU. Now calls the same
extraction logic as the non-fragmented path.

**AAC AudioSpecificConfig always wrote AOT = 2 (LC) (`build_audio_specific_config`, `muxer/mp4.rs`)**
Regardless of the `AacProfile` passed by the caller. Now correctly encodes
AOT 1 (Main), 2 (LC), 3 (SSR), 4 (LTP), 5 (HE), or 29 (HE-v2).

**`mdhd` duration silently truncated for clips > 13.6 hours (`muxer/mp4.rs`)**
A `u64 → u32` cast wrapped without error. Now uses a version-1 (64-bit) mdhd box
when `duration > u32::MAX` timescale units.

**`is_hevc_keyframe` panicked on empty input (`codec/h265.rs`)**
`assert_invariant!(INV-503)` panicked on empty data instead of returning `false`.
Replaced with a graceful early return.

## MP4 Spec Compliance

- **`build_vmhd_box` flags corrected**: ISO 14496-12 §12.1.2 requires `flags = 1`. Was 0.
- **`mvhd` `next_track_ID`**: Was hardcoded to 2 even with audio present. Now 2 (video-only) or 3 (video+audio).
- **`tkhd` track duration was always 0**: ISO 14496-12 §8.3.2 requires the `duration` field to carry the track duration in movie timescale. Both video and audio `tkhd` boxes now receive the computed duration instead of 0. This is the remaining item from PR #4 and PR #6.

---

## Dead Invariants Removed

Four `assert_invariant!` guards that could never fire (tautologies after prior guards)
were removed from `codec/av1.rs`, `codec/h264.rs`, and `codec/vp9.rs`. Keeping dead
assertions is misleading — they imply a condition could be violated when it cannot.

---

## API / Code Quality

- `Muxer<W>` and `MuxerBuilder<W>` now implement `Debug`.
- `MuxerError::FirstVideoFrameMissingSpsPps` Display updated to mention H.265 NAL types 32/33/34.
- `encode_language_code` de-duplicated: single canonical implementation in `mp4.rs` used by both the standard and fragmented paths.
- `FragmentedError` marked `#[non_exhaustive]`.
- `Vp9Config` derives `Eq`.
- `AudioValidationConfig.channels` and `validate_audio_config` parameter promoted from `u8` to `u16`.

---

## New Example

`examples/interop_av_h264_aac.rs` — end-to-end functional test that generates real H.264
video and AAC audio via ffmpeg, muxes them with the library API, then validates with
ffprobe and a full decode pass. Both tracks confirmed `disposition:default=1`.

---

## Upgrade Notes

No API-breaking changes. All changes are backward-compatible bug fixes and additions.
